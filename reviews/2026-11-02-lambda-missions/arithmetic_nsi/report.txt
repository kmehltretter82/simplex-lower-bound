Review of An Arithmetic for Non-Size-Increasing Polynomial-Time Computation
Snapshot: proposal-before-review.json, proposal c900846e-090f-48cb-99cd-869a4ce1bf09.
Reviewed 2026-11-02. No remote changes made.

Verdict: changes required. The submitted soundness-of-typing theorem has a kernel-checked counterexample. The cleaning definition loses a required iterator argument. All eleven natural-language item descriptions also conflict with their current formal content. These are mathematical/metadata defects, not missing proofs of valid statements.

P1 — Theorem 4.7 is false on one valid equality-transport axiom.
Affected target: ABHS2004.theorem_4_7, theorem ID 4d154f33-9db8-4048-8df3-fd719b97a5dc.
Locations: code/02_ABHS2004_Realizability.lean:133; code/07_ABHS2004_theorem_4_7.lean:4; tau in code/01_ABHS2004_Arithmetic.lean:211.
Take CoreAxiom.ax16 diamond x x with x a diamond variable. This is a valid axiom and yields a derivation in empty contexts. FreshRealizerVars holds because the derivation uses no assumption variables. The axiom formula is x=diamond x → Ediamond(x) → Ediamond(x). Its extracted type tau is U ⊸ diamond ⊸ diamond, but extractAxiom returns id_diamond, whose type is diamond ⊸ diamond. Thus the first conjunct of theorem_4_7 fails.

Evidence: counterexamples.lean contains the exact three definition modules, followed by badAx_valid, badAx_derivable, badAx_fresh, and badAx_extraction_not_typed. It compiles in Lean 4.33.1 using the pinned environment; the printed axiom dependencies are only propext and Quot.sound, with no sorryAx. No mission theorem is imported into the certificate.

Repair: give the uncleaned realizer an ignored U argument, e.g. λ e^U, z^diamond. z, and then let cleaning remove it. Audit the entire axiom extraction table against tau rather than assuming each displayed source shorthand is already an explicitly typed term. The author PDF itself displays id_ρ here (Definition 4.3, PDF p.21), so record this as a necessary explicit elaboration/correction of source shorthand; do not silently repeat the untyped expression.

P1 — Cleaning list iteration is incompatible with the submitted iterator type.
Location: code/02_ABHS2004_Realizability.lean:344.
The iterator's typed step always has diamond ⊸ ρ ⊸ τ ⊸ τ. When cleanTy ρ = U, cleanTerm removes the step's ρ binder, but the .iter constructor still expects the original three-argument step over the cleaned element type U. A closed typed L(U) iterator can therefore clean to a term with no weak type. Root's independently checked CleanIteratorAudit.lean gives this exact counterexample. This affects the definition underlying Theorems 4.7/4.9 and the main extraction target; a direct false theorem_4_7 certificate is already supplied by the ax16 example above.
Repair: adapt cleaned iterator step terms with a dummy U argument (and address cleaned accumulator-unit cases), or formalize an explicitly adjusted cleaned calculus. Prove type-preserving cleaning for all well-typed terms before reusing it in extraction. Source Definition 4.4's displayed c(r{s}) shorthand needs explicit elaboration compatible with the chosen raw syntax, just as the code already adapts cons when element type cleans to U.

P1 — Exact coefficient-one syntactic-size bounds need correction.
Affected targets: theorem_2_25 (781d5724-8400-4aaa-b8e9-a80da0140554), corollary_4_11 (bf94660f-3637-40e8-ba3b-06853916376b).
The output condition termLength w ≤ totalTermLength ws + k is stronger than preservation of diamond-token size across different data types. A closed affine map from L(U) to L(U+U), replacing each unit element ε by inl ε, preserves tokens but changes the uploaded termLength from 3n+1 to 4n+1 on length-n inputs. No fixed additive k bounds this difference for all n. Root is independently checking and documenting the size convention. Source Definition 2.24 explicitly describes syntactical length as comparable to size up to a type-dependent constant; the formal target fixes the coefficient at one. Use the intended token/resource size exactly, or allow type-dependent multiplicative constants for syntactic length. Do not equate asymptotic comparability with an exact coefficient-one inequality.

P1 — Every natural-language item description conflicts with its formal content.
See metadata-comparison.txt for the exact snapshot fields. Examples: TermSystem describes a !-modal two-context calculus and denotational evaluator that are absent from the code; Arithmetic describes N-HA^ω, Peano axioms and strictly-positive binary induction instead of this paper's E-predicate/list-induction calculus; corollary_4_8 describes extraction/substitution commutation while the Lean target states three underivability claims. The independent readbacks mostly describe the code correctly and contradict the older natural-language descriptions.
Repair: rewrite every title/description/milestone from the final Lean and paper; regenerate independent readbacks after definition/theorem corrections. Since these are already-published reference items, corrected formal statements need replacement items, not just a draft-proposal prose edit.
